Quick Delete 1.2.2 is an original Valenced-native plugin.
Source: https://github.com/Fluttershy2008-mlp/lol/tree/main/valenced/plugins/quick-delete

Valenced API reference: Valenced/valenced revision 17008ad2eb170da4b7aaca35ad8154bb09a60a8a.
The MessagesHandlers.params integration follows Valenced's community
message-link-preview plugin's native chat integration. Native-view tap wrapping
also supports builds whose params getter cannot be replaced.
Confirmation identifiers were checked against the native message menu and the
public QuickDelete implementation in Purple-EyeZ/RevengePlugins; no code is copied.

Native settings registration was checked against Valenced 4fb12ba (1.2.4).
Reply calls Discord's modules/replies/native/replyToMessage.tsx or the native
PendingReplyActionCreators fallback with the same action-sheet source and
mention defaults. Active composer lookup uses utils/native/ChatInputUtils.tsx.
Reference: https://github.com/Wumpus-Central/discord-mobile-datamining/tree/c8275f9989c8572f5d441e162c7109b9c6497068/discord_app/modules/replies

Automated tests cover lifecycle, permission checks, native message events,
localized prompts, duplicate requests, failures, cancellation, reply drafts,
current-chat keyboard focus and the native Valenced settings entry.
The direct reply and direct delete settings are mutually exclusive; conflicting
saved values prefer reply. Existing saved preferences and package ID are retained.
Reply scheduling now has no idle dependency for direct taps and a bounded wait
for menu taps. Cold-start fallback uses the native CREATE_PENDING_REPLY and
MESSAGE_END_EDIT events. Three new regression checks fail on 1.2.0 and pass on
the repaired build; native composer capture is scoped to channel and account.
Physical Android interaction has not been tested in this environment.
